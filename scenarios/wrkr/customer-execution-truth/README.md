# Customer execution truth

This scenario uses a synthetic four-organization structural twin. The committed
oracle is independently authored and counts files, references, relationships,
operations, and runtime consumers. It contains no customer names, paths, source,
or values and does not import production classification logic.

The semantic layer covers nested and case-varied Jenkins entrypoints, mapped and
unmapped shared libraries, dynamic script references, GitHub reusable workflows
and composite actions, GitLab includes, Azure templates, parser failure, generic
and generated OpenAPI documents, a static Swagger consumer, and structured
identity-schema contamination. Inert repositories multiply this same topology to
384 and 674 repositories without changing the semantic oracle.
